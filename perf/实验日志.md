# 实验日志

每条一次改动，只记录实际做过的实验。测量口径统一 Fast 4G，冷缓存，10 次取 p75。

## 1. 拆分站点图标（保留）

- 假设：612KB 的 1024×1024 PNG 被拉两次纯属浪费，拆成 favicon 32px + apple-touch-icon 180px 可省约 1.2MB。
- 改动：`public/icon-32.png`（1.1KB）、`public/icon-180.png`（7.4KB）；
  `layout.tsx` 的 favicon/apple-touch-icon、`site-icon.ts` 默认值、`manifest.json` 指向新文件。
- 计数：完整加载图片字节 1,225,972 B → 约 9KB。
- 真实耗时：对 ready p75 无明显影响（图标不在关键路径）——符合预期，保留是因为慢网下省带宽。
- 视觉：桌面/移动像素差 0.01%（阈值内）。

## 2. 首页拆成服务端页面 + 客户端岛（保留，为 4 铺路）

- 假设：`app/page.tsx` 整页 `'use client'` + `useSearchParams` 导致 SSR 阶段整页 bail out。
- 改动：`app/page.tsx` 改为服务端组件，`await searchParams` 后把 `initialQuery` 传给
  `components/home/HomePageClient.tsx`；`useHomePage` 不再读 `useSearchParams`。
- 计数：SSR HTML 仍无 `<input>`——单独看无改善（ready 638→626ms，噪声内）。
- 结论：必要铺垫（消除页面级 bail out 来源），保留。

## 3. Suspense 包裹 ssr:false 动态组件（保留，为 4 铺路）

- 假设：`dynamic(..., { ssr: false })` 的 `FavoritesSidebar` 无条件渲染，
  SSR 时抛 CSR bailout 拖垮整个子树。
- 改动：`HomePageClient` 里给 SearchResults / PopularFeatures / FavoritesSidebar
  各包一层 `<Suspense fallback={null}>`；`layout.tsx` 给 `ScrollPositionManager` 同样处理
  （静态页预渲染需要）。
- 计数：仍无 `<input>`——单独看无改善，真正堵点是 PasswordGate（见 4）。
- 结论：保留，防御未来 ssr:false 组件再次拖垮整页 SSR。

## 4. PasswordGate 在无密码站点放行 SSR（保留，主贡献）

- 假设：`PasswordGate` 的 `if (!isClient) return null` 让所有页面在 SSR 阶段输出空壳；
  当服务端未配置任何密码（`hasAuth === false`）时提前渲染 children 没有安全风险。
- 改动：`isLocked` 初始值 `initialHasAuth`、`isClient` 初始值 `!initialHasAuth`；
  配置了密码的站点行为不变（SSR 仍输出空壳，客户端校验后才渲染）。
- 计数：SSR HTML `<input>` 0 → 1；关键路径请求 19 → 12；字节 210KB → 62KB。
- 真实耗时（串行 10 次）：ready p75 638ms → 287ms。
- 安全验证：`ADMIN_PASSWORD` 模式下 curl SSR HTML 无搜索框/无内容泄漏，
  浏览器水合后正确显示锁屏。
- 结论：保留，主贡献。

## 5. 配对终测（结论数据）

- A/B 同场交替各 10 次（含 1 轮预热）：A p75 580.3ms，B p75 262.6ms，**-54.7%**。
